## 📚 核心内容

### 1. 同步的痛点：等待占用了时间

```python
import time

def download(url):
    time.sleep(2)          # 模拟一次网络请求，耗时 2 秒
    print(f"{url} 下载完成")

start = time.time()
for url in ["a", "b", "c"]:
    download(url)          # 一个个等
print(f"总耗时 {time.time() - start:.2f}s")
# a 下载完成
# b 下载完成
# c 下载完成
# 总耗时 6.00s   ← 三个 2 秒串行累加，其实大部分时间在「干等网络返回」
```

> 关键：`time.sleep(2)` 里，CPU 什么都没干，纯在**等**。同步代码的问题不是「慢」，是「等的时候没法去干别的」。

### 2. 协程：`async` / `await`

```python
import asyncio

async def download(url):       # async 定义一个「协程函数」
    await asyncio.sleep(2)     # await 在这里「挂起」，把控制权交出去
    print(f"{url} 下载完成")
```

**调用 ≠ 执行**（呼应生成器）：

```python
result = download("a")         # 只拿到一个协程对象，函数体没跑
print(type(result))            # <class 'coroutine'>
# 想真正执行，必须交给事件循环（见第 4 节）
```

### 3. 事件循环：单线程如何「同时」跑多个任务

**服务员比喻**：一个服务员（单线程）同时服务多桌。A 桌点完菜等上菜（`await` 挂起），服务员转身去 B 桌点菜——不是干等，而是**在等待期间切换去做别的**。

```python
import asyncio

async def task(name, secs):
    print(f"{name} 开始")
    await asyncio.sleep(secs)   # 挂起，让出控制权
    print(f"{name} 结束")

async def main():
    await asyncio.gather(
        task("A", 3),
        task("B", 1),
    )

asyncio.run(main())
# A 开始
# B 开始
# B 结束   ← 1 秒后（B 等得短，先结束）
# A 结束   ← 3 秒后
# 总耗时 ≈ 3 秒，而不是 4 秒
```

> asyncio 是**单线程 + 协作式调度**：不是真的并行（同一时刻只有一个任务在跑 CPU），而是「谁在等待，就把时间让给别的任务」。这正是它和多线程的根本区别——多线程靠操作系统抢占切换，asyncio 靠 `await` 主动让出。

### 4. `asyncio.run()`：入口

```python
asyncio.run(main())   # ① 创建事件循环 → ② 运行 main 协程 → ③ 关闭循环
```

一个程序只调一次 `asyncio.run()`，它是把协程「送进事件循环」的唯一大门。

### 5. 并发执行：`gather` 和 `create_task`

```python
# 方式一：gather — 一批一起等，返回结果列表
async def main():
    results = await asyncio.gather(
        fetch("a"), fetch("b"), fetch("c"),
    )
    print(results)   # [结果a, 结果b, 结果c]

# 方式二：create_task — 手动创建任务，各自独立
async def main():
    t1 = asyncio.create_task(fetch("a"))
    t2 = asyncio.create_task(fetch("b"))
    await t1; await t2
```

| | `gather` | `create_task` |
|---|---|---|
| 用途 | 一次性并发跑一批，拿结果 | 手动管理每个任务，更灵活 |
| 返回值 | 结果列表 | 任务对象（再 `await` 拿结果）|

### 6. 最关键的坑：`asyncio.sleep` vs `time.sleep`

```python
import asyncio, time

async def good():
    await asyncio.sleep(3)   # ✅ 挂起，事件循环去跑别的任务

async def bad():
    time.sleep(3)            # ❌ 阻塞整个事件循环，其他任务全卡死
```

> 这是新手最常犯的错：在协程里用了普通阻塞函数（`time.sleep`、`requests`、文件读写），整个事件循环会被堵死，并发瞬间退化成串行。原则：**协程里一切「等待」都要用 `await` 的异步版本**。

### 7. 三种并发方案怎么选（衔接 PY026/PY027）

| 场景 | 选 asyncio | 选多线程 | 选多进程 |
|------|-----------|---------|---------|
| IO 密集（网络、爬虫、API） | ✅ 首选，单线程搞定高并发 | ✅ 也可以 | ❌ 太重 |
| CPU 密集（计算） | ❌ 会卡死循环 | ❌ 受 GIL 限制 | ✅ 真正并行 |

### 8. 误区 / 边界

1. **写了 `async def` 但没 `await`** → 调用只是拿到协程对象，什么都不会发生
2. **在协程里用阻塞函数** → 事件循环被卡死，并发失效（见第 6 节）
3. **把 CPU 密集任务放 asyncio** → 单线程算不过来，不如直接用多进程
4. **以为 asyncio 是多线程** → 它是单线程协程，靠 `await` 协作式切换
