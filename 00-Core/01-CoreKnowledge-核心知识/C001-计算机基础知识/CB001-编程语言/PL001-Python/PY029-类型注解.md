## 📚 核心内容

Python 是**动态类型**语言：变量的类型在运行时才确定，同一个变量可以先存 `int` 再存 `str`。这让代码很灵活，但也带来几个实打实的麻烦——函数签名看不懂、传错类型要到运行时才炸、IDE 无法智能补全。

**类型注解（Type Hints，PEP 484）** 就是为解决这些痛点引入的。先记住最关键的一条：

> ⚠️ **类型注解只是"注释"，运行时完全不检查。** Python 不会因为注解写了 `int` 就拒绝传入 `str`。它的价值是给**人**和**IDE/静态工具（mypy）**看的。

```python
def add(a: int, b: int) -> int:
    return a + b

add(1, 2)      # ✅ 正常返回 3
add("a", "b")  # ⚠️ 运行时不会报错！返回 "ab"（字符串拼接）
```

### 基本语法

类型注解分两类：**变量注解**和**函数签名注解**。

```python
# ① 变量注解：变量名: 类型 = 值
name: str = "Alice"
age: int = 30
scores: list[int] = [90, 85, 92]

# ② 函数参数注解 + 返回值注解（-> 类型）
def greet(name: str) -> str:
    return f"Hello, {name}"

# ③ 没有返回值 → 标注 None
def log(msg: str) -> None:
    print(msg)
```

> `-> str` 表示返回值类型；`-> None` 表示不返回任何有用的值（约等于 `return` 或不写 `return`）。

### 常用类型

基本类型直接用内置类型即可，`Optional` / `Union` / `Any` 需从 `typing` 导入：

```python
from typing import Optional, Union, Any

# 基本类型：直接用内置类型名
def process(x: int, ratio: float, ok: bool) -> str:
    ...

# Optional[T] = T 或 None —— 最常用的场景："可能返回 None"
def find_user(user_id: int) -> Optional[str]:
    if user_id == 1:
        return "Alice"
    return None              # ✅ 合法，Optional[str] 允许 None

# Union[X, Y] = X 或 Y —— 一个参数/返回值允许多种类型
def parse(value: str) -> Union[int, float]:
    if "." in value:
        return float(value)
    return int(value)

# Any = 任意类型 —— 逃逸口，相当于"关闭这一处的类型检查"
def magic(data: Any) -> Any:
    return data.something()
```

| 类型写法 | 含义 | 何时用 |
|----------|------|--------|
| `int` / `str` / `float` / `bool` | 基础类型 | 大多数情况 |
| `list` / `dict` / `tuple` / `set` | 容器（裸类型，不看内部元素） | 不关心元素类型时 |
| `Optional[T]` | `T` 或 `None` | 函数可能返回 `None` |
| `Union[X, Y]` | `X` 或 `Y` | 一个位置允许多种类型 |
| `Any` | 任意类型 | 动态代码、迁移旧代码时兜底 |

> **Python 3.10+ 的现代写法**：`Optional[str]` 可写作 `str | None`，`Union[int, float]` 可写作 `int | float`，更直观。旧项目里 `Optional`/`Union` 仍很常见，两种都要会读。

### 泛型：`list[int]`、`dict[str, int]`

裸的 `list` 只说明"是列表"，没说里面装什么。**泛型**就是给容器加上"元素类型"：

```python
# Python 3.9+：内置容器直接支持下标，无需 import
names: list[str] = ["Alice", "Bob"]          # 字符串列表
scores: dict[str, int] = {"math": 90}        # 键是 str，值是 int 的字典
pair: tuple[int, str] = (1, "one")           # 二元组：(int, str)

# 旧写法（Python 3.8 及以前，需从 typing 导入大写版本）
from typing import List, Dict, Tuple
names: List[str] = ["Alice", "Bob"]
scores: Dict[str, int] = {"math": 90}
```

```python
def average(nums: list[int]) -> float:
    return sum(nums) / len(nums)

average([1, 2, 3])      # ✅
average(["a", "b"])     # ❌ mypy 会报错：list[str] 不能传给 list[int]
```

> 裸 `list` 和 `list[int]` 的区别，就像"一箱货"和"一箱苹果"——后者能让人知道里面是什么，出错了也更好定位。

### mypy：类型检查工具

类型注解本身不检查类型，真正做检查的是 **mypy**——它在**不运行代码**的情况下扫描代码，找出类型不匹配的地方：

```bash
pip install mypy
```

```python
# demo.py
def add(a: int, b: int) -> int:
    return a + b

result = add(1, "2")   # 这里传了 str
```

```bash
mypy demo.py
# demo.py:5: error: Argument 2 to "add" has incompatible type "str"; expected "int" [arg-type]
```

> mypy 是"静态"检查——它读源码推演类型，不执行代码。所以它能抓到 `add(1, "2")` 这种要跑起来才会爆的错误。IDE（VS Code/PyCharm）内置了同样的能力，写代码时实时标红。

**mypy 的错误是"提示"不是"报错"**：即使 mypy 报错，程序照样能运行。它是开发期的守门员，不是运行时。

### 进阶（可选）：`TypeVar`、`Protocol`、`dataclass`

```python
# TypeVar —— 泛型函数：保持"输入类型 = 输出类型"
from typing import TypeVar
T = TypeVar("T")

def first(items: list[T]) -> T:
    return items[0]

first([1, 2, 3])      # 返回 int
first(["a", "b"])     # 返回 str
# 关键：first 不会把 int 列表变成 str，T 保证了类型一致

# Protocol —— 结构化类型（鸭子类型的静态版）
from typing import Protocol

class Flyable(Protocol):
    def fly(self) -> None: ...

def takeoff(obj: Flyable) -> None:
    obj.fly()
# 任何定义了 fly() 方法的对象都能传入，不必显式继承 Flyable

# dataclass —— 自动生成 __init__/__repr__ 等样板代码
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

p = Point(1, 2)      # 自动生成构造函数
print(p)             # Point(x=1, y=2)  自动生成可读的 __repr__
```

### 练习 1：补全函数注解

给下面的函数补上合适的类型注解：

```python
def add_user(user_id, name, age):
    """新增用户，返回是否成功"""
    if age < 0:
        return None
    return {"id": user_id, "name": name, "age": age}
```

> [!info]- 答案
> ```python
> from typing import Optional
>
> def add_user(user_id: int, name: str, age: int) -> Optional[dict[str, object]]:
>     if age < 0:
>         return None
>     return {"id": user_id, "name": name, "age": age}
> ```
> - `age < 0` 时返回 `None`，所以返回值是 `Optional[...]`
> - 字典的键都是 `str`，值有 `int` 也有 `str`，所以是 `dict[str, object]`

### 练习 2：判断哪些注解错误

下面哪些写法是错误的（或会被 mypy 报错）？

```python
a: int = "hello"                    # ①
def f(x: int) -> str: return x      # ②
def g(x: Optional[int]) -> int: return x   # ③
nums: list[int] = [1, "2"]          # ④
```

> [!info]- 答案
> 全部都会被 mypy 报错（但运行时都能跑）：
> - ① `int` 变量赋了 `str`
> - ② 声明返回 `str`，实际返回了 `int`
> - ③ `Optional[int]` 可能是 `None`，不能直接当 `int` 返回（需先判空）
> - ④ `list[int]` 里混入了 `str` 元素
>
> 这正是类型注解的价值——这些隐患不用跑代码，mypy 一眼就能看出来。

## 🤔 常见误区

1. **误区：「写了类型注解，Python 就会在运行时检查类型」**
   **事实**：不会。注解是纯"文档"，运行时被忽略。真正的检查靠 mypy 或 IDE。想让运行时也检查，得用 `pydantic`、`typeguard` 这类第三方库。

2. **误区：「加了注解代码会跑得更快」**
   **事实**：标准 Python（CPython）不会利用注解做优化，性能基本不变。注解的价值是可读性和静态检查，不是提速。

3. **误区：「`Any` 是万能的，哪里不确定就写 `Any`」**
   **事实**：`Any` 等于"关闭这一处的类型检查"，滥用 `Any` 等于没写注解。只有确实无法确定类型（如处理第三方动态数据）时才用，且应尽量收窄范围。

4. **误区：「`Optional[X]` 和 `Union[X, None]` 是两个东西」**
   **事实**：`Optional[X]` 就是 `Union[X, None]` 的简写，完全等价。Python 3.10+ 又都等价于 `X | None`。

5. **误区：「`list[int]` 从 Python 一出生就能用」**
   **事实**：内置容器下标（`list[int]`）是 Python 3.9 才支持的。更早版本必须 `from typing import List` 用 `List[int]`。现在的项目（3.9+）直接用 `list[int]` 即可。
