> Claude Code 的「记忆层」核心是 `CLAUDE.md` 文件——每次会话开始自动加载的持久化指令手册，让 Claude 能跨会话记住项目约定、编码规范和工作流。

## 什么是 CLAUDE.md

`CLAUDE.md` 是一个 **纯 Markdown 文件**，作为 Claude Code 的**持久化指令手册**。与对话上下文（会话结束即清空）不同，CLAUDE.md 在**每次会话开始时自动加载**，为 Claude 提供：

+ 项目上下文和架构信息
+ 编码规范与风格约定
+ 开发命令与工作流
+ 跨会话持久化的规则与指南

Claude 在写任何代码**之前**就会先读这些文件，所以它是影响 Claude 行为最直接的手段。

## 五层作用域

CLAUDE.md 文件可以存在于 **5 个层级**，从最广到最具体：

| 层级 | 位置 | 作用域 | 是否共享 |
|------|------|--------|----------|
| **1. 企业策略** | `managed-settings.json` 中定义 | 整个组织 | ❌ IT 管理 |
| **2. 用户全局** | `~/.claude/CLAUDE.md` | 你所有的项目 | ❌ 私有 |
| **3. 项目级** | `<项目根>/CLAUDE.md` 或 `.claude/CLAUDE.md` | 特定项目 | ✅ 提交到 Git |
| **4. 项目本地** | `<项目根>/CLAUDE.local.md` | 特定项目（个人） | ❌ 被 gitignore |
| **5. 子目录级** | 任意子文件夹中的 `CLAUDE.md` | 仅该目录 | ✅ 提交到 Git |

### 各层的典型用途

| 层级 | 典型内容 |
|------|----------|
| **用户全局** | 个人编码偏好、默认工作流、通用风格 |
| **项目级** | 团队共享的架构约定、命名规范、构建命令、Do/Don't |
| **项目本地** | 本地环境差异、个人调试配置（不提交） |
| **子目录级** | 模块特有的约定（如 `frontend/CLAUDE.md` 写前端规范） |
| **企业策略** | 合规要求、安全标准（IT 统一管理） |

## 加载顺序与优先级

**加载顺序**（从先到后）：

```
企业策略 → 用户全局 → 项目级 → 项目本地 → 子目录级（按需）
```

关键行为：

+ **叠加而非覆盖**：所有层级的内容**拼接**在一起进入 Claude 的上下文，不是互相替代
+ **后加载 = 高优先级**：当不同层的指令冲突时，**更具体**（更晚加载）的文件优先
+ **子目录按需加载**：只有当 Claude 读取某个目录下的文件时，才会加载该目录的 CLAUDE.md
+ **可用 `claudeMdExcludes` 跳过**：在 `settings.json` 中配置，可排除特定 CLAUDE.md 文件

## 推荐内容结构

### 10 节模板

```markdown
# CLAUDE.md

## 1. 项目概述
项目是什么、做什么、当前状态

## 2. 技术栈
语言、框架、库（带版本号）
- **前端:** React 19.2, Next.js 15
- **后端:** Node.js 22, Express 5
- **数据库:** PostgreSQL 16, Prisma 6

## 3. 架构
关键设计决策、目录结构、数据流

## 4. 编码规范
命名、格式化、Lint 规则、风格偏好

## 5. UI & 设计系统
组件库、主题、可访问性规则

## 6. 开发命令
构建、测试、部署的**精确命令**
- `npm run dev` — 启动开发服务器
- `npm run test` — 运行单元测试

## 7. 测试
测试框架、模式、覆盖率要求

## 8. 常用模式
重复性任务的首选方案

## 9. 禁止项 / 反模式
Claude 应该避免的事情
- 永远不要用 `any` 类型
- 永远不要提交 console.log

## 10. 关键文件 & 入口
Claude 需要知道的重要文件
```

## 最佳实践

### 内容原则

+ **具体**："用 2 空格缩进" 比 "格式化代码" 有效得多
+ **带版本**："React 19.2" 而不只是 "React"
+ **简洁**：理想长度 **80–120 行**；每多一行都在稀释重要内容的注意力
+ **强调**：关键规则用 **粗体** 或大写
+ **给真实命令**：能在项目里直接跑的命令
+ **列反模式**：明确的 "禁止做 X" 能防止常见错误
+ **保持更新**：反映**实际决策**，不是**愿望清单**
+ **积极修剪**：像代码一样维护它

### 结构原则

+ **合理分层**：全局放个人偏好，项目放团队规范，本地放个人覆盖
+ **大文件拆分**：用 `.claude/rules/` 目录按主题拆分成多个规则文件
+ **善用引用**：用 `@import` 指向长文档，而不是复制粘贴
+ **避免代码块**：聚焦**规则和规范**，不是代码示例
+ **不要放密钥**：共享的 CLAUDE.md 里**永远不要**写 API Key 或凭证

## 限制与坑

### 硬限制

| 限制 | 说明 |
|------|------|
| 字符上限 | 单个规则文件 ≤ **6000 字符**，所有规则合计 ≤ **12000 字符** |
| 实际行数 | 80–120 行是信噪比最优区间 |
| 上下文压力 | Claude 200K token 上下文有限；冗长的 CLAUDE.md 浪费每轮 token |

### 行为特性

+ **软指导，非强制**：CLAUDE.md 被视为上下文而非强制配置。Claude "会遵守直到做不到，然后靠自己的判断填空"
+ **矛盾会出问题**：两条规则互相冲突，Claude 可能**随机选一条**
+ **上下文衰减**：长对话中注意力会退化，早期内容被弱化
+ **Token 成本**：CLAUDE.md 中的**每个 token 每次请求都要计费**
+ **无运行时强制**：CLAUDE.md 只能**引导** Claude，不能**阻止**它做某事

### 常见错误

+ ❌ 文件太长（500+ 行）
+ ❌ 塞代码示例（应放单独文档）
+ ❌ 多个文件间信息冗余
+ ❌ 不更新，内容与实际脱节
+ ❌ 当成" growing 笔记本"不断加内容，而不是**精炼的配置**

## 相关记忆机制

Claude Code 有**多个记忆层**协同工作：

| 机制 | 持久性 | 用途 |
|------|--------|------|
| **CLAUDE.md** | ✅ 持久（跨会话） | 用户手写的持久指令 |
| **Auto Memory** | ✅ 持久 | Claude **自动**记录的测试命令、失败命令、用户纠正 |
| **Session Memory** | ❌ 临时 | 单次对话内维持，会话结束清空 |
| **settings.json** | ✅ 持久 | 配置（权限、模型、MCP 服务器）——**硬覆盖**，优先级与 CLAUDE.md 相反 |

### `.claude/` 目录结构

| 子系统 | 文件 | 用途 |
|--------|------|------|
| **指令** | `CLAUDE.md`, `rules/` | 行为规则与规范 |
| **设置** | `settings.json` | 配置、权限、模型设置 |
| **工作流** | `skills/`, `commands/` | 自定义 slash 命令与技能 |
| **子代理** | `agents/` | 子代理定义 |
| **记忆** | `MEMORY.md`（自动生成） | Auto Memory 存储 |

> 💡 **settings.json vs CLAUDE.md**：settings.json 是**配置**（硬覆盖），CLAUDE.md 是**指导**（软指令）。settings.json 的优先级是 Managed > Local > Project > User（与 CLAUDE.md 的叠加方向相反）。
