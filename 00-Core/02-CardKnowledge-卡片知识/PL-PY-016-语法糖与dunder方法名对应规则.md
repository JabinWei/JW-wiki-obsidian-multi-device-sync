## 💡 核心概念

==Python 语言规范硬绑定：你写的每个运算符/语法（`a + b`、`len(a)`、`a[i]`、`a(...)`），执行时都会调用一个固定名字的双下划线方法（dunder method）。== 这不是记忆题，是规则。完整调用形式永远是 `type(a).__xxx__(a, b)`——**从类上找方法，不是从实例上找**。

---

## 🔍 详细说明

### 一、完整调用形式：到底传几个参数？

最容易被简写误导的地方。以 `a + b` 为例，严格等价于：

```python
type(a).__add__(a, b)
#  ↑      ↑    ↑    ↑
#  类    方法 self  other
#            =a    =b
```

代入具体类型就很直观：

```python
3 + 5
# 等价于 int.__add__(3, 5)             → 8
"abc" + "def"
# 等价于 str.__add__("abc", "def")     → "abcdef"
```

> ⚠️ 下面表格为了简洁用简写 `type(a).__add__(b)`，**省略了 self**。实际调用时 `a` 一定作为第一个参数传入。

### 二、算术运算符对应表

| 语法 | 方法（简写） | 含义 |
|------|------------|------|
| `a + b` | `__add__` | 加法 |
| `a - b` | `__sub__` | 减法 subtraction |
| `a * b` | `__mul__` | 乘法 multiplication |
| `a / b` | `__truediv__` | 真除法 |
| `a // b` | `__floordiv__` | 地板除 |
| `a % b` | `__mod__` | 取模 modulo |
| `a ** b` | `__pow__` | 幂运算 power |
| `a @ b` | `__matmul__` | 矩阵乘（Py3.5+） |

### 三、比较与位运算符

| 语法 | 方法 | 语法 | 方法 |
|------|------|------|------|
| `a == b` | `__eq__` | `a << b` | `__lshift__` |
| `a != b` | `__ne__` | `a >> b` | `__rshift__` |
| `a < b` | `__lt__` | `a & b` | `__and__` |
| `a <= b` | `__le__` | `a \| b` | `__or__` |
| `a > b` | `__gt__` | `a ^ b` | `__xor__` |
| `a >= b` | `__ge__` | `~a` | `__invert__` |

### 四、常用内置语法

| 语法/内置函数 | 方法 |
|--------------|------|
| `len(a)` | `__len__` |
| `str(a)` / `repr(a)` | `__str__` / `__repr__` |
| `a[i]` / `a[i] = v` / `del a[i]` | `__getitem__` / `__setitem__` / `__delitem__` |
| `a(...)` | `__call__` |
| `with a:` | `__enter__` / `__exit__` |
| `iter(a)` / `next(a)` | `__iter__` / `__next__` |
| `int(a)` / `float(a)` / `bool(a)` | `__int__` / `__float__` / `__bool__` |
| `abs(a)` / `hash(a)` | `__abs__` / `__hash__` |

### 五、关键细节：从类上找，不从实例上找

Python 执行 `a + b` 时，找 `__add__` 是从 `type(a)`（类）上找，**忽略实例字典**。这是为了保证运算符行为稳定——你不能给某个实例挂个同名属性就改变 `+` 的语义。

### 六、反射方法：`r` 前缀

每个二元算术运算符都有反射版本（详见 [[PL-PY-015-运算符双分派协商机制]]）：

- `__add__` → `__radd__`
- `__sub__` → `__rsub__`
- `__mul__` → `__rmul__`

比较运算符**没有** `r` 前缀版本——`a < b` 失败时，会反过来试 `b > a`（用 `__gt__`），这是富比较的对称性。

## 📎 例子

### 实例属性骗不过运算符

```python
class Foo:
    def __add__(self, other):
        return "我是类上的 __add__"

a = Foo()
a.__add__ = lambda other: "我是实例上伪装的 __add__"

a + 1          # → "我是类上的 __add__"（运算符走类方法，不被欺骗）
a.__add__(1)   # → "我是实例上伪装的 __add__"（普通属性查找，先实例后类）
```

**为什么 `a + 1` 不被欺骗？** 运算符规则要求 dunder 必须从类型（类）上查找，忽略实例字典里的同名属性。这就是 `a + b` 和 `a.__add__(b)` 在边缘情况下不等价的原因。

### 用 `dir()` 反向查

```python
dir(5)
# ['__abs__', '__add__', '__and__', '__bool__', ...]
```

看到 `__add__` 就知道支持 `+`，看到 `__lt__` 就知道支持 `<`。

### 用 `operator` 模块验证

```python
import operator
operator.add(3, 5)    # 8，等价于 3 + 5
operator.eq(3, 5)      # False
operator.lt(3, 5)      # True
```

## ⚡ 反例 / 边界

1. **不要给实例挂 dunder 想改变运算符行为**：运算符从类上找，实例字典的同名属性对 `+`、`==`、`[]` 完全无效。
2. **不能凭印象命名**：真除法是 `__truediv__` 不是 `__div__`（Py3 已废弃 `__div__`）；矩阵乘是 `__matmul__`（不是 `__mul__`）。
3. **比较运算符没有反射版本**：以为有 `__rlt__`？没有。`<` 的反射是借用 `>` 的 `__gt__`。
4. **`__eq__` 不写时默认用身份比较**：`a == b` 等价于 `a is b`，不会报错。
5. **简写 `a.__add__(b)` 不是运算符的完整等价**：日常写代码没问题，但在理解协议时要记住完整形式是 `type(a).__add__(a, b)`。
